## 1. PHÂN TÍCH CỔ CHAI LFM2.5-1.2B-Instruct

### Kiến trúc LFM2.5 vs Transformer

LFM2.5 là mô hình **lai Recurrent + Attention** (Liquid Foundation Model):

- **Recurrent layers** (chiếm đa số): Nén context thành trạng thái cố định → O(1) memory per decode step, KHÔNG đọc KV cache.
- **Attention layers** (thiểu số, GQA): Vẫn dùng KV cache nhưng rất ít layers → bandwidth thấp hơn nhiều so với Transformer thuần.

### Breakdown TPOT = 4ms (FP8 Weights, Batch ≈ 32 sequences)

| Thành phần                          | Thời gian ước tính | Tỉ lệ |
| :---------------------------------- | :----------------: | :---: |
| **Weight reads (FP8, 1.2GB)**       |      ~1.75 ms      |  44%  |
| **KV cache reads (attention)**      |      ~0.60 ms      |  15%  |
| **Recurrent state update**          |      ~0.40 ms      |  10%  |
| **Computation (MatMul + Act)**      |      ~0.50 ms      |  13%  |
| **Overhead (kernel launch, sched)** |      ~0.75 ms      |  18%  |
| **Tổng**                            |    **~4.00 ms**    | 100%  |

> [!IMPORTANT]
> **Phát hiện then chốt**: Weight reads chiếm **44%** thời gian TPOT. Đây là đòn bẩy lớn nhất. Giảm kích thước weights từ FP8 (1 byte) xuống INT4 (0.5 byte) sẽ giảm ~0.87ms, kéo TPOT xuống ~3.1ms. Kết hợp CUDA Graphs giảm overhead kernel launch, tiềm năng đạt ~2.5ms.

### Track A: Custom Docker Image + Custom Kernels & Online FP8 ⭐ (ƯU TIÊN #1)

**Mục tiêu**: Giảm TPOT từ 4ms → ~2.8ms, TTFT từ 76ms → ~55ms.

> [!IMPORTANT]

> Do đó, Track A tập trung vào việc dùng Custom Docker Image để **tiêm (inject) custom Triton/CUDA kernels** tăng tốc tính toán trực tiếp trên weights gốc và KV Cache được lượng tử hóa online.

#### Bước 1: Viết và tối ưu hóa Custom Triton/CUDA Kernels cho LFM recurrent layers

Viết custom kernels tối ưu hóa các phép tính tuần hoàn (gated short-convolution blocks) của LFM2.5 và fusion layers (như LayerNorm + Linear + Activation) để chạy trực tiếp trên GPU.

#### Bước 2: Build Custom Docker Image (tái sử dụng hạ tầng Round 1)

```dockerfile
FROM vllm/vllm-openai:v0.22.1

# Cài đặt các custom kernels đã compiled
COPY ./custom_kernels /app/custom_kernels
RUN cd /app/custom_kernels && pip install .

# Setup hijack script để tiêm custom kernels lúc start
COPY ./hijack /app/hijack
ENV VLLM_CUSTOM_KERNEL=1
```

```bash
# Build và push image lên Docker Hub
docker build -t ptquanh/sandbox-runtime:vllm-lfm25-fp8-kernels-v1 .
docker push ptquanh/sandbox-runtime:vllm-lfm25-fp8-kernels-v1
```

#### Bước 3: Docker Compose chạy với Custom Image & Online FP8

```yaml
services:
  model:
    image: ptquanh/sandbox-runtime:vllm-lfm25-fp8-kernels-v1
    environment:
      - OMP_NUM_THREADS=2
    entrypoint:
      - python3
      - -m
      - vllm.entrypoints.openai.api_server
    command:
      - --model=/model # Giữ nguyên model gốc theo đúng quy định BTC

      - --host=0.0.0.0
      - --port=8000
      - --max-model-len=32768
      - --gpu-memory-utilization=0.95
      - --tensor-parallel-size=1
      - --enable-prefix-caching
      - --quantization=fp8 # Sử dụng online quantization hợp lệ của vLLM
      - --no-enable-log-requests
      - --disable-log-stats
      - --max-num-seqs=32
      - --enable-chunked-prefill
      - --max-num-batched-tokens=4096
    ports:
      - "8000:8000"
    shm_size: "2g"
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
```

## 2. KẾ HOẠCH THỬ NGHIỆM 15 SLOTS TRÊN NỀN CUSTOM IMAGE

> [!IMPORTANT]
> Toàn bộ 15 slots của ngày 18/07 sẽ chạy **100% trên nền Custom Docker Image** `ptquanh/sandbox-runtime:vllm-lfm25-fp8-kernels-v1` để thừa hưởng cơ chế Warmup JIT (loại bỏ trễ khởi chạy) và tối ưu hóa Triton kernels.
> Cấu hình nền tảng kế thừa từ **STT 16 ngày 17/07 (58.94 điểm)** kết hợp với các tối ưu hóa của Custom Image.

> [!NOTE]
> **Sự khác biệt của Custom Image so với Stock Image:**
>
> 1. **Warmup JIT**: Thực hiện chạy thử một số request ảo lúc startup để ép GPU khởi tạo và compile JIT các kernel tuần hoàn trước khi Grader tiến hành đo đạc, triệt tiêu hoàn toàn trễ khởi động (giảm TTFT của lượt request đầu tiên).
> 2. **Triton Custom Kernels**: Tích hợp các nhân CUDA/Triton tự biên dịch đặc thù cho recurrent layers của LFM2.5 để tối ưu hóa weight reads (chiếm 44% TPOT) và giảm overhead scheduling.

#### Nhóm 1: Custom Image Baseline & Compilation (4 slots)

_Mục tiêu: Đo lường hiệu năng của Custom Image đơn thuần so với Stock Image, đồng thời đánh giá hiệu quả của torch.compile trên nền image này._

| Slot | Cấu hình thay đổi so với Baseline Custom Image | Mục tiêu                                                                                                                                                                     |
| :--: | :--------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|  1   | Không thay đổi (Baseline Custom Image)         | So sánh Custom Image (có Warmup JIT + Custom Kernel hook) với Stock Baseline cao điểm nhất hiện tại (**STT 16 ngày 17/07: 58.94 điểm**) chạy cùng tham số (OMP=2, FP8 Base). |
|  2   | + `--compilation-config '{"level": 3}'`        | Bật tối ưu hóa torch.compile aggressive (operator fusion + CUDA graph nâng cao).                                                                                             |
|  3   | + `--compilation-config '{"level": 2}'`        | So sánh với level 3 để chọn mức compile an toàn nhất.                                                                                                                        |
|  4   | + `--enforce-eager`                            | Tắt hoàn toàn CUDA Graphs để đo baseline thuần eager trên custom image.                                                                                                      |

#### Nhóm 2: Scheduler & Batching Tuning (3 slots)

_Mục tiêu: Tìm kiếm điểm ngọt (sweet-spot) của chunk size và block size trên custom image._

| Slot | Cấu hình thay đổi so với Baseline Custom Image | Mục tiêu                                                                   |
| :--: | :--------------------------------------------- | :------------------------------------------------------------------------- |
|  5   | + `VLLM_MAX_NUM_BATCHED_TOKENS=3072`           | Chunk size 3072 (giữa 2048 và 4096) — tìm điểm sweet-spot chi tiết hơn.    |
|  6   | + `VLLM_MAX_NUM_BATCHED_TOKENS=5120`           | Chunk size 5120 — kiểm tra xem prefill lớn hơn 4096 có hiệu quả hơn không. |
|  7   | + `--block-size=8`                             | Giảm block size KV cache từ 16 (mặc định) xuống 8 → giảm phân mảnh bộ nhớ. |

#### Nhóm 3: N-gram Speculative Decoding (3 slots)

_Mục tiêu: Đánh giá N-gram Speculative trên nền Custom Image._

| Slot | Cấu hình thay đổi so với Baseline Custom Image                                                 | Mục tiêu                                                                      |
| :--: | :--------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------- |
|  8   | + `--speculative-model [ngram]` + `--ngram-prompt-lookup-max=4` + `--num-speculative-tokens=3` | N-gram 4-token window, sinh 3 token speculative → đánh giá tác động lên TPOT. |
|  9   | + `--speculative-model [ngram]` + `--ngram-prompt-lookup-max=6` + `--num-speculative-tokens=5` | N-gram 6-token window, sinh 5 token speculative → mức aggressive hơn.         |
|  10  | + `--speculative-model [ngram]` + `--ngram-prompt-lookup-max=3` + `--num-speculative-tokens=2` | N-gram 3-token window, sinh 2 token speculative → mức conservative.           |

#### Nhóm 4: Hardware & Concurrency Tuning (5 slots)

_Mục tiêu: Đánh giá tác động của Triton custom kernels, tối ưu hóa cơ chế async output và hàng đợi đồng thời._

| Slot | Cấu hình thay đổi so với Baseline Custom Image | Mục tiêu                                                                                                       |
| :--: | :--------------------------------------------- | :------------------------------------------------------------------------------------------------------------- |
|  11  | `VLLM_CUSTOM_KERNEL=0`                         | Tắt Triton kernels (giữ Warmup) để đo trực tiếp chênh lệch tốc độ của base stock layer (không custom kernels). |
|  12  | + `--disable-async-output-proc`                | Tắt xử lý output không đồng bộ để giảm CPU scheduling jitter trên host 3 cores.                                |
|  13  | + `VLLM_MAX_NUM_SEQS=48`                       | Tăng concurrency lên 48 để giải phóng hàng đợi prefill.                                                        |
|  14  | + `VLLM_MAX_NUM_SEQS=24`                       | Giảm concurrency xuống 24 để tối ưu hóa TPOT của bước decode.                                                  |
|  15  | Combo tối ưu nhất                              | Ghép combo các nhân tố tốt nhất tìm được từ Slot 1-14.                                                         |
