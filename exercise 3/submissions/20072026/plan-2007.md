### Tại sao Max Model Len 8192 có thể là đột phá?

Theo [challenge_specification.md](file:///d:/CODE%20PLAYGROUND/Projects/Competitions/Viettel%20AI%20Race/exercise%203/docs/challenge_specification.md#L171-L183):

- Context tối đa trong trace chỉ là **~4700 tokens** (Turn 6: 4400 input + 300 output)
- Thiết lập `--max-model-len=8192` (thay vì 32768) sẽ:
  1. **Giải phóng ~75% VRAM dành cho KV Cache** → Nhiều VRAM hơn cho compute
  2. **Giảm đáng kể thời gian warmup CUDA Graph** (ít shape variants cần compile)
  3. **Tăng hiệu quả prefix caching** (ít phân mảnh bộ nhớ)
  4. **Giảm overhead scheduling** của vLLM block manager

### TẦNG 2: Image v3 — Speculative Decoding với Draft Model nhúng (20-22/07)

_Mục tiêu: 65-75 điểm. Cần build Docker image mới._

> [!IMPORTANT]
> **Ý tưởng cốt lõi**: Tải sẵn model `LiquidAI/LFM2.5-350M-Instruct` (~350MB) và nhúng vào Docker image tại đường dẫn `/draft_model`. Khi khởi chạy, vLLM sẽ tải draft model từ filesystem cục bộ (không cần mạng).

**Kế hoạch xây dựng Image v3:**

1. **Download model 350M offline** → `huggingface-cli download LiquidAI/LFM2.5-350M-Instruct`
2. **Thêm vào Dockerfile**: `COPY ./LFM2.5-350M-Instruct /draft_model`
3. **Cập nhật `python3_hijack`**: Thêm xử lý `VLLM_SPECULATIVE_MODEL=/draft_model`
4. **Test local** trước khi push lên Docker Hub

**Cấu hình nộp bài Speculative Decoding:**

```yaml
environment:
  - VLLM_SPECULATIVE_MODEL=/draft_model
  - VLLM_NUM_SPECULATIVE_TOKENS=3
  - VLLM_COMPILATION_LEVEL=0 # Tránh deadlock JIT + Speculative
  - VLLM_MAX_MODEL_LEN=8192 # Giải phóng VRAM cho 2 models
  - VLLM_QUANTIZATION=fp8
```

**Phân tích kỹ thuật:**

- Draft model 350M (~350MB FP8) + Target model 1.2B (~1.2GB FP8) = ~1.55GB weights
- 18GB VRAM — 1.55GB weights = ~16.45GB cho KV Cache, CUDA Graphs, activations
- Speculative tokens=3 với acceptance rate ~70-80% → Effective TPOT giảm ~2x → **TPOT ≈ 2ms**
- **Dự kiến điểm số: 75-80+ điểm** nếu speculative hoạt động

**Rủi ro cần lưu ý:**

- ⚠️ Kiến trúc Hybrid Recurrent của LFM2.5 **có thể không tương thích** với speculative decoding trên vLLM v0.22.1 (cần test)
- ⚠️ `COMPILATION_LEVEL=0` (không JIT compile) sẽ tăng TTFT — cần cân đối
- ⚠️ Nếu dùng `COMPILATION_LEVEL=3` + speculative → Rủi ro deadlock (đã xảy ra với N-gram)
